# Проверка выпуска 1.2.2

Единственный установочный ZIP — `netchat-wp-1.2.2.zip`: папка `netchat/`, 60 файлов. SHA256: `d485bfadf9dec04443a2131d4311c7d3c1d9f69d73fdbae5b052e2d026acd160`. Манифест закреплён в `tools/release-1.2.2.manifest.json`. Сборщик отказывается выпускать другие байты или перезаписывать отличающийся архив. Встроены ровно два нейтральных примера форм. Пользовательские данные, `.git`, стенды, тесты и локальные отчёты в ZIP не входят.

## Что проверяется

- Состав, CRC и SHA256 каждого файла; воспроизведение принятого ZIP; версия 1.2.2 в заголовке, константе и stable tag.
- Синтаксис PHP/JS и прежние проверки SQL, форм, переноса данных, прав и приватности.
- Почтовой шаблон: русские тексты, время сайта, экранирование HTML, защита заголовков и ссылок, HTML/plain MIME, очистка временных обработчиков, Reply-To/From, успех, ошибка, исключение и повтор отправки. Реальные письма не отправляются.
- [GitHub Actions](https://github.com/omhotey/WP-NetChat/actions/workflows/ci.yml): один ZIP собирается на Windows и передаётся обеим парам WordPress 5.0 / PHP 7.2 и WordPress 7.1.3 / PHP 8.3. Проверяются установка, переустановка, миграция JSON из 1.0.0, обновление с 1.2.0, сохранность данных и браузерные сценарии. Для прежнего имени папки выполняется явный переход в `netchat/`; второй ZIP не создаётся.
- Локальная проверка принятого пакета 21 октября: 41 проверка браузера и HTTP на ширинах 1440/390, token 200, submission 201, идемпотентность, русское HTML/plain письмо в Mailpit и сохранность данных NetChat. Тестовые записи откатились, временные файлы и письмо удалены. Для прокрутки использовалась временная вставка в DOM; заявка отправлялась напрямую через REST.

Точные run/commit нового выпуска указаны на странице релиза после завершения CI. Старые теги, архивы и результаты 1.2.0 сохраняются; старый PASS не заменяет проверку новой версии.

## Границы результата

Во временном браузерном ядре CI автоматический cron-loopback отключён из-за однопроцессного PHP-сервера. Настоящие обработчики запускаются через WP-CLI, их расписание проверяется. Это не доказывает автоматический cron на рабочем сайте. Тема, кеш/CDN, документы, реальные устройства, полный UI-submit и внешняя доставка проверяются отдельно. Владелец сообщил о работе после ручного обновления; независимая проверка production этим выпуском не заявляется.

В Git публикуются исходники, синтетические тесты и документация. Локальные снимки, выгрузки, ключи, настройки и формы владельца не публикуются.
