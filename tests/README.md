## Изоляция hosted CI

`compatibility-ci.sh` и браузер порогов требуют `GITHUB_ACTIONS=true`; они не создают локальный runtime автоматически. `NETCHAT_CORE_DIR` задаёт временное ядро, `NETCHAT_RELEASE_DIR` — каталог точных артефактов. CI использует отдельный MySQL service/database и удаляет свои временные данные при завершении. Локальные Docker-службы и volumes не используются.

Playwright 1.56.1 и Chromium устанавливаются только во временном hosted worker. WP-CLI 2.12.0 закреплён SHA256 официального release asset. После SQL и ZIP-проверок с обычными настройками автоматический HTTP-cron отключается только во временном ядре для браузерных сценариев. Два обработчика очереди запускаются явно через WP-CLI с проверкой результата и отключённой отправкой почты. Это не подтверждает работу cron или доставку SMTP на рабочем сайте.

Результат матрицы не является проверкой реальных устройств, конкретной темы, page cache/CDN или получения письма адресатом. Дополнительные локальные сценарии ниже запускаются отдельно и не получают результат автоматически из hosted CI.

## Локальный запуск и дополнительные проверки

Для локального запуска подготовьте отдельный стенд по [инструкции WordPress Lab](../tools/wordpress-lab/README.md) и заполните placeholders из `.env.example`. Проверяйте фактические версии WordPress/PHP: закреплённый образ не доказывает версию ядра в существующем volume. Резервные копии владелец делает отдельно; проверки автоматически их не создают.

Перед runner вручную скачайте [исторический публичный ZIP v1.0.0](https://github.com/omhotey/WP-NetChat/releases/download/v1.0.0/WP-NetChat-main.zip) в `dist/release-1.2.0/historical-v1.0.0.zip` и проверьте SHA256:

```powershell
(Get-FileHash -LiteralPath 'dist/release-1.2.0/historical-v1.0.0.zip' -Algorithm SHA256).Hash
# EAD4077F9A746370715D286546927F449E2B28EF3434F03C1A9C587FD1D38B7D
```

При несовпадении хеша остановитесь; другой архив не является проверенным fixture обновления.

```powershell
pwsh -File tests/run.ps1
```

Проверяются PHP-синтаксис, Node-регрессии, хранилище на настоящем WordPress и установочный ZIP. `wp-integration.php` запускается с `--skip-plugins=netchat`, затем подменяет только options-таблицу на временную таблицу текущего соединения и загружает NetChat. Синтетический JSON находится в `/tmp`. Рабочие options и JSON не заменяются этими fixtures.

`release-smoke.sh` создаёт отдельный временный каталог WordPress и таблицы с уникальным префиксом `nc_release_`. Проверяет чистую установку, переустановку ZIP, повторную активацию и сохранение данных при стандартном удалении. В конце удаляет только свои тестовые таблицы и временный каталог. При аварийном завершении контейнера могут остаться таблицы `nc_release_*`; их следует проверить отдельно.

Браузерные тесты требуют Playwright и установленный Chromium либо Edge. Зависимость можно взять из готового runtime, указав путь к модулю; пакет не входит в поставку плагина.

```powershell
$env:PLAYWRIGHT_MODULE_PATH = 'path/to/existing/node_modules/playwright'
$env:BROWSER_CHANNEL = 'msedge'
node tests/service-forms-e2e.mjs
```

`e2e.mjs` читает порты стенда из `.env`. Через WP-CLI создаёт временную 30-минутную сессию администратора только на локальном сайте и отзывает её в `finally`; пароль и остальные сессии сохраняются. На время проверки сохраняет синтетические контакты через админку и восстанавливает исходную конфигурацию в `finally`. Ревизия при этом увеличивается. Не запускайте тест параллельно с ручным редактированием настроек. При принудительном прерывании теста восстановите конфигурацию из резервной копии.

`forms-lifecycle-storage.php` проверяет создание, дублирование, выключение,
удаление, новые вопросы и сохранность заявки в отдельных тестовых таблицах.
`forms-lifecycle-e2e.mjs` проходит этот путь в браузере, включая реальную отправку
синтетической заявки и поиск после удаления формы. Собственная заявка удаляется,
конфигурация форм восстанавливается и сравнивается с исходной. Ширины: 320/390/1440 px.

Проверки браузера: восемь каналов, повторное сохранение, отключённые контакты и флаги, нулевые задержки, конфликт revision, неверные типы/домены, запрет гостю, Viber href, reduced-motion, Escape и левая позиция на мобильном экране. Снимок синтетического виджета сохраняется в `tests/results/`.

Исторический набор проверок заявок: `leads-storage.php` создаёт отдельные таблицы с префиксом `nc_leads_test_*` и временную options-таблицу. Проверяет заявки, ошибки и повторы почты (без реальных писем), согласие, лимиты, privacy на 52 записях, сроки хранения, права и экранирование. После выполнения удаляет только свои таблицы. Браузер дополнительно проверяет форму без каналов/видимой кнопки, фокус и retry после сетевого сбоя, три одновременных HTTP POST с одним ключом, настройки формы и защищённые действия админки. Синтетическая заявка удаляется; исходная конфигурация восстанавливается.

ZIP проверяется также на сохранение заявки при обычном uninstall и полную очистку собственных таблиц/очередей при явном `NETCHAT_DELETE_DATA=true` в изолированном экземпляре WordPress.

Дополнительные локальные сценарии проверяют отдельный экран успеха, закрытие формы после прокрутки на мобильном экране, отступы и закрытие приветствия, немедленный ручной повтор уведомления и получение синтетического письма в Mailpit. Снимки формы и настроек сохраняются в `tests/results/`.

Описания дополнительных локальных сценариев не являются результатом их нового запуска. Проверка page cache/CDN, почты и открытия приложений мессенджеров на устройствах требует отдельного стенда.

`forms-usability-inspect.mjs` проверяет доступность действий каталога без горизонтальной
прокрутки, отдельный мобильный предпросмотр и контактный шаг, отсутствие ложного статуса
несохранённых правок при заполнении предпросмотра, размеры публичного диалога на
320/390/1440 px, фокус при ошибке согласия и сохранность ответа при переходе назад.
Сохраняет снимки `tests/results/ux-*.png` для визуального осмотра. Жизненный цикл
дополнительно проверяет восстановление вкладки/вопроса/шага после сохранения,
запрет случайного сохранения через Enter в предпросмотре, раскрытие ошибочного вопроса,
включение формы из редактора, фокус после выбора контакта мышью и клавиатурой.

Редактор контактной формы проверяется на 390/1440 px: выбор поля, мгновенное
обновление подписи/видимости/заголовка в предпросмотре, статусы изменений,
вкладки и стрелки клавиатуры, мобильный возврат из предпросмотра. Заполнение
предпросмотра не меняет настройки. `e2e.mjs` сохраняет поля из разных вкладок
и проверяет независимость настроек виджета и обоих вариантов сброса.

Каталог услуг: фильтры по состоянию и размещению, поиск вместе с фильтром,
счётчик результатов, пустой результат и сброс. Проверяются единственное
открытое меню действий, закрытие через Escape и отсутствие переполнения
при раскрытом меню на 320 px. Снимки `ux-catalog-*.png`.

Для привязок предварительно создайте локальные пустые страницы:
`docker compose --project-directory D:/Project/WordPress-Lab -f D:/Project/WordPress-Lab/compose.yaml run --rm --no-deps wpcli eval-file /var/www/html/wp-content/plugins/netchat/tools/setup-service-pages-lab.php`.
Этот отдельный, явно запускаемый скрипт оставляет страницы и привязки на стенде.
`page-bindings-e2e.mjs` — отдельный исторический suite: проверяет все страницы, прямой вход,
UTM/ID, альтернативные каналы, выключенный канал/отсутствие каналов, закрытие
черновика, фокус и 320/390/1440 px. Временные настройки восстанавливает в finally.

`setup-common-form-lab.php` создаёт обычную общую форму в локальном каталоге.
`widget-opening-e2e.mjs` проверяет оба режима, один столбец, крупную форму сверху,
общую форму/чекбокс, редактирование её текста на главной, замену/снятие маркера,
приоритет страницы/явной кнопки, сохранность документов и привязок. Снимки
`common-form-*.png`, `home-common-form-*.png`, `widget-menu-*.png`.

## Изолированные проверки кандидата 1.2.1

Общий tests/run.ps1 выше относится к прежним runtime-сценариям 1.2.0 и не запускается автоматически для этого кандидата. Без общего WordPress выполните node tests/interaction-007.test.mjs. Команда node tests/interaction-007-e2e.mjs использует уже установленный Playwright/Edge (PLAYWRIGHT_MODULE_PATH / BROWSER_CHANNEL), собственный HTML и явно перехваченный синтетический транспорт: это browser fixture, не actual WordPress. Проверяются modal/drawer слева/справа, 320/390/1440, порядок контактов, отсутствие details, пустые контакты, фоны, focus/Escape/inert/scroll/reduced-motion, pending success/503/реальные 20 секунд.

Команда node tests/interaction-007.test.mjs --php-bundle выдаёт чистый PHP в stdout для установленного PHP; standalone режим использует явные WP doubles без SQL и файлов. Файл interaction-007-wp.php на настоящем WordPress требует заранее загруженного кандидата и session-owned TEMPORARY options с префиксом nc007_ и явным nc007_isolated_options. Прямой запуск на общей options запрещён. Отдельное QA-окно и изоляцию готовит Оркестратор; старые mutating SQL/e2e здесь не запускаются. Ни зависимости, ни сервисы не устанавливаются.
