# Проверки NetChat

Для добавления порогов прокрутки в 1.2.0 hosted `compatibility-ci.sh` запускает `scroll-visibility-e2e.mjs` на настоящем одноразовом WordPress/MySQL, после service/transfer suites. Новый браузерный тест требует `GITHUB_ACTIONS=true`; локально сам не создаёт runtime. HTML, REST, admin save/reload, scroll geometry, history, ResizeObserver/MutationObserver fallback и импорт проверяются реальными запросами/DOM без mock PASS. Выходы: `dist/release-1.2.0/scroll-browser` (синтетические screenshots и verification.json). Service suite теперь пересекает пороги при pending A→B; прежние success/503/20-second timeout assertions сохраняются. `wp-integration.php` и `data-transfer-storage.php` расширены реальными изолированными SQL-проверками старого конфига, строгих процентов, raw CAS и отсутствующих/лишних null-ветвей. Подготовка тестов не означает их выполнение; финальный PASS фиксируется только по фактической матрице.

## Hosted CI совместимости

Для ревизии с переносом данных дополнительно подготовлены `data-transfer-storage.php`, `data-transfer-e2e.mjs` и `distribution-privacy.test.cjs`. SQL-проверки используют собственную таблицу nc_transfer_*; проверяют полный bundle, копирование/замену, legacy one-step, неизвестные/null/повторные данные, лимиты, InnoDB и rollback второй записи. Hosted браузер читает скачанный JSON, проверяет реальные права/nonce, preview без записи, copy/replace, stale/digest, клавиатуру и 320/390 px. Hosted `service-forms-e2e.mjs` сохраняет success/error/timeout pending-регрессии на семи нейтральных синтетических схемах; они не являются встроенными формами продукта. Эти новые SQL/browser сценарии имеют статус НЕ_ЗАПУЩЕНО до фактического выполнения. Playwright 1.56.1 и Chromium ставятся только в временном hosted worker; локальный runtime не устанавливается.

Workflow `Release compatibility` подготовлен для точных пар WordPress 5.0 / PHP 7.2 и WordPress 7.1.3 / PHP 8.3. До фактического успешного GitHub Actions run обе hosted-пары имеют статус **НЕ_ЗАПУЩЕНО**. Официальный архив WordPress подтверждает доступность этих версий; WP-CLI 2.12.0 закреплён SHA256 официального release asset.

Windows job собирает два ZIP и manifests из того же checkout. Runtime jobs скачивают именно эти artifacts, сверяют архив/каждый файл/manifest с исходниками и запускают `bash tests/compatibility-ci.sh`. Скрипт работает только на временном GitHub Actions worker, получает точное ядро с проверкой core checksums и версии, использует отдельный MySQL service/database, выполняет PHP lint, JS normalization и пять существующих WP-CLI integration suites без подмен API. Затем проверяет clean install, историческое обновление 1.0.0, сохранность и явное удаление на этих ZIP. Исторический архив проверяется по SHA256 до создания smoke fixture.

`NETCHAT_CORE_DIR` задаёт временное ядро для smoke, `NETCHAT_RELEASE_DIR` — каталог exact artifacts. База CI и собственные временные каталоги удаляются в cleanup. Это не команда настройки локального Docker: локальные службы и volumes не используются. Статусы ниже описывают предыдущую локальную проверку и не заменяют результат hosted-матрицы. Последующий PASS должен ссылаться на конкретный Actions run/commit; реальные устройства и production-site остаются отдельной проверкой.

Проверенный локальный стенд: `D:\Project\WordPress-Lab`, WordPress 7.1.3 / PHP 8.3.33. Для нового checkout пользователь вручную подготавливает отдельный локальный стенд по публичным материалам `tools/wordpress-lab` и заполняет placeholders из `.env.example`. Закреплённый образ WordPress 7.0.4 не доказывает версию ядра в существующем volume: проверяйте фактические версии через WordPress/PHP. Резервные копии владелец делает отдельно; эти проверки автоматически их не создают.

Перед runner вручную скачайте [исторический публичный ZIP v1.0.0](https://github.com/omhotey/WP-NetChat/releases/download/v1.0.0/WP-NetChat-main.zip) в `dist/release-1.2.0/historical-v1.0.0.zip` и проверьте SHA256:

```powershell
(Get-FileHash -LiteralPath 'dist/release-1.2.0/historical-v1.0.0.zip' -Algorithm SHA256).Hash
# EAD4077F9A746370715D286546927F449E2B28EF3434F03C1A9C587FD1D38B7D
```

При несовпадении хеша остановитесь; другой архив не является проверенным fixture обновления.

```powershell
pwsh -File tests/run.ps1
```

Проверяются PHP-синтаксис, Node-регрессии, хранилище на настоящем WordPress и установочный ZIP. `wp-integration.php` запускается с `--skip-plugins=netchat`, затем подменяет только options-таблицу на временную таблицу текущего соединения и загружает NetChat. Синтетический JSON находится в `/tmp`. Рабочие options и JSON не заменяются этими fixtures.

`release-smoke.sh` создаёт отдельный временный каталог WordPress и таблицы с уникальным префиксом `nc_release_`. Проверяет чистую установку, переустановку ZIP, повторную активацию и сохранение данных при стандартном удалении. В конце удаляет только свои тестовые таблицы и временный каталог. При аварийном завершении контейнера могут остаться таблицы `nc_release_*`; их следует проверить отдельно.

Браузерные тесты требуют Playwright и установленный Chromium либо Edge. Зависимость можно взять из готового runtime, указав путь к модулю; пакет не входит в поставку плагина.

```powershell
$env:PLAYWRIGHT_MODULE_PATH = 'path/to/existing/node_modules/playwright'
$env:BROWSER_CHANNEL = 'msedge'
node tests/service-forms-e2e.mjs
```

`e2e.mjs` читает порты стенда из `.env`. Через WP-CLI создаёт временную 30-минутную сессию администратора только на локальном сайте и отзывает её в `finally`; пароль и остальные сессии сохраняются. На время проверки сохраняет синтетические контакты через админку и восстанавливает исходную конфигурацию в `finally`. Ревизия при этом увеличивается. Не запускайте тест параллельно с ручным редактированием настроек. При принудительном прерывании теста восстановите конфигурацию из резервной копии.

`forms-lifecycle-storage.php` проверяет создание, дублирование, выключение,
удаление, новые вопросы и сохранность заявки в отдельных тестовых таблицах.
`forms-lifecycle-e2e.mjs` проходит этот путь в браузере, включая реальную отправку
синтетической заявки и поиск после удаления формы. Собственная заявка удаляется,
конфигурация форм восстанавливается и сравнивается с исходной. Ширины: 320/390/1440 px.

Проверки браузера: восемь каналов, повторное сохранение, отключённые контакты и флаги, нулевые задержки, конфликт revision, неверные типы/домены, запрет гостю, Viber href, reduced-motion, Escape и левая позиция на мобильном экране. Снимок синтетического виджета сохраняется в `tests/results/`.

Для версии 1.1 `leads-storage.php` создаёт отдельные таблицы с префиксом `nc_leads_test_*` и временную options-таблицу. Проверяет заявки, ошибки и повторы почты (без реальных писем), согласие, лимиты, privacy на 52 записях, сроки хранения, права и экранирование. После выполнения удаляет только свои таблицы. Браузер дополнительно проверяет форму без каналов/видимой кнопки, фокус и retry после сетевого сбоя, три одновременных HTTP POST с одним ключом, настройки формы и защищённые действия админки. Синтетическая заявка удаляется; исходная конфигурация восстанавливается.

ZIP проверяется также на сохранение заявки при обычном uninstall и полную очистку собственных таблиц/очередей при явном `NETCHAT_DELETE_DATA=true` в изолированном экземпляре WordPress.

Для 1.1.1 дополнительно проверяются отдельный экран успеха, закрытие формы после прокрутки на мобильном экране, отступы и закрытие приветствия, немедленный ручной повтор уведомления и получение синтетического письма в Mailpit. Снимки формы и настроек сохраняются в `tests/results/`.

Прохождение этих проверок на текущем стенде не заменяет проверку минимальных PHP/WordPress, page cache/CDN и реального открытия приложений мессенджеров на устройствах.

`forms-usability-inspect.mjs` проверяет доступность действий каталога без горизонтальной
прокрутки, отдельный мобильный предпросмотр и контактный шаг, отсутствие ложного статуса
несохранённых правок при заполнении предпросмотра, размеры публичного диалога на
320/390/1440 px, фокус при ошибке согласия и сохранность ответа при переходе назад.
Сохраняет снимки `tests/results/ux-*.png` для визуального осмотра. Жизненный цикл
дополнительно проверяет восстановление вкладки/вопроса/шага после сохранения,
запрет случайного сохранения через Enter в предпросмотре, раскрытие ошибочного вопроса,
включение формы из редактора, фокус после выбора контакта мышью и клавиатурой.

Редактор контактной формы проверяется на 390/1440 px: выбор поля, мгновенное
обновление подписи/видимости/заголовка в предпросмотре, статусы изменений,
вкладки и стрелки клавиатуры, мобильный возврат из предпросмотра. Заполнение
предпросмотра не меняет настройки. `e2e.mjs` сохраняет поля из разных вкладок
и проверяет независимость настроек виджета и обоих вариантов сброса.

Каталог услуг: фильтры по состоянию и размещению, поиск вместе с фильтром,
счётчик результатов, пустой результат и сброс. Проверяются единственное
открытое меню действий, закрытие через Escape и отсутствие переполнения
при раскрытом меню на 320 px. Снимки `ux-catalog-*.png`.

Для привязок предварительно создайте локальные пустые страницы:
`docker compose --project-directory D:/Project/WordPress-Lab -f D:/Project/WordPress-Lab/compose.yaml run --rm --no-deps wpcli eval-file /var/www/html/wp-content/plugins/netchat/tools/setup-service-pages-lab.php`.
Этот отдельный, явно запускаемый скрипт оставляет страницы и привязки на стенде.
`page-bindings-e2e.mjs` — отдельный исторический suite: проверяет все страницы, прямой вход,
UTM/ID, альтернативные каналы, выключенный канал/отсутствие каналов, закрытие
черновика, фокус и 320/390/1440 px. Временные настройки восстанавливает в finally.

`setup-common-form-lab.php` создаёт обычную общую форму в локальном каталоге.
`widget-opening-e2e.mjs` проверяет оба режима, один столбец, крупную форму сверху,
общую форму/чекбокс, редактирование её текста на главной, замену/снятие маркера,
приоритет страницы/явной кнопки, сохранность документов и привязок. Снимки
`common-form-*.png`, `home-common-form-*.png`, `widget-menu-*.png`.

## Проверка кандидата 1.2.0

Новый output: `dist/release-1.2.0`. Общий `-Browser` runner блокируется: исторические suites сохраняют старые `tests/results`. Их описания выше не означают, что они запускались для этого кандидата. Запускайте `service-forms-e2e.mjs` отдельно с `NETCHAT_TEST_OUTPUT` под `dist/release-1.2.0`. Сценарии pending A→close→B покрывают успех, 503 и реальный 20-секундный timeout; закрытие не отменяет запрос. Full-service-email тест остаётся неизменным. Smoke использует проверенный `historical-v1.0.0.zip` с root `WP-NetChat-main` и совместимый upgrade ZIP. Минимальная PHP/WP матрица и GitHub CI не считаются выполненными из локального PASS.
